# Memory Drop

Memory Drop — кроссплатформенное мобильное приложение для создания цифровых воспоминаний и сообщений, которые могут быть привязаны к определённому месту.

## Цель проекта

Создать Flutter-приложение, в котором пользователь сможет создавать Memory Drops, сохранять воспоминания, просматривать их и в дальнейшем открывать сообщения в зависимости от геолокации.

## Целевая аудитория

Подростки, студенты и взрослые, которые хотят сохранять важные воспоминания, оставлять цифровые послания и делиться ими.

## Основные функции и планы

- создание Memory Drop;
- просмотр списка Drops;
- просмотр деталей Drop;
- добавление в избранное;
- поиск;
- локальное хранение;
- светлая и тёмная темы;
- работа без интернета;
- геолокация и карта;
- авторизация;
- push-уведомления.

## Week 3 — Управление состоянием

На третьей неделе функция добавления воспоминаний в избранное была последовательно реализована с помощью setState, InheritedWidget и Provider.

### setState

Первоначально функция избранного была реализована через `setState`.

Плюсы:
- простой и понятный подход;
- встроен во Flutter;
- хорошо подходит для небольшого локального состояния.

Минусы:
- состояние связано с конкретным StatefulWidget;
- неудобно использовать одно состояние на нескольких экранах;
- при росте приложения код становится сложнее поддерживать.

### InheritedWidget

Затем состояние было перенесено на `InheritedWidget`.

Плюсы:
- встроен во Flutter;
- позволяет передавать состояние дочерним виджетам;
- не требует дополнительной библиотеки.

Минусы:
- требуется больше кода;
- управление состоянием сложнее читать;
- необходимо самостоятельно реализовывать обновление через updateShouldNotify.

### Provider

Финальная реализация функции избранного выполнена через `Provider`.

Плюсы:
- меньше шаблонного кода;
- удобно отделять состояние от пользовательского интерфейса;
- одно состояние можно использовать в разных виджетах;
- ChangeNotifier позволяет уведомлять интерфейс об изменении данных через notifyListeners.

Минусы:
- требуется дополнительная зависимость;
- при большом количестве Provider структура проекта может усложняться.

### Вывод

`setState` удобно использовать для простого локального состояния одного экрана.

`InheritedWidget` подходит для передачи состояния по дереву виджетов, но требует больше ручного кода.

`Provider` оказался удобнее для общего состояния приложения, поэтому он используется как итоговый подход на третьей неделе.


## Week 4 — Продвинутое управление состоянием

На четвёртой неделе основная логика приложения была перенесена на Riverpod.

Проект был разделён на три основных слоя:

### Presentation

Отвечает за пользовательский интерфейс и взаимодействие с пользователем.

Содержит экраны и Riverpod providers.

### Domain

Содержит основную бизнес-логику приложения.

В этом слое находятся сущность MemoryDrop и интерфейс DropRepository.

### Data

Отвечает за получение и изменение данных.

DropRepositoryImpl реализует интерфейс DropRepository.

### Repository Pattern

UI не работает с данными напрямую.

Экран обращается к Riverpod, Riverpod использует Repository, а Repository предоставляет данные.

### Dependency Injection

Dependency Injection реализован через Riverpod.

DropRepository создаётся через отдельный Provider и передаётся в DropsNotifier через ref.

### Почему Riverpod

Riverpod был выбран для основной логики приложения, потому что:

- состояние отделено от UI;
- удобно работать с зависимостями;
- не требуется BuildContext для получения состояния;
- подходит для масштабирования приложения;
- может одновременно использоваться для state management и Dependency Injection.


## Week 5 — Работа с REST API и JSON

На пятой неделе приложение было подключено к REST API.

Для тестового backend используется MockAPI, а сетевые запросы выполняются через Dio.

### REST API

Приложение получает список воспоминаний через:

GET /drops

Также используется обновление избранного:

PUT /drops/:id

### JSON

Для преобразования JSON используется `json_serializable`.

Создана отдельная модель `MemoryDropModel`, которая преобразует данные API в доменную сущность `MemoryDrop`.

### Состояния загрузки

Для сетевых данных реализованы состояния:

- loading — данные загружаются;
- success — данные успешно загружены;
- error — произошла ошибка сети;
- empty — сервер вернул пустой список.

Состояния обрабатываются через Riverpod и `AsyncValue`.

### Pull-to-refresh

На экране воспоминаний используется `RefreshIndicator`.

Пользователь может потянуть список вниз, после чего приложение повторно запрашивает данные с сервера.

### Поиск с debounce

Добавлен поиск по названию воспоминания и местоположению.

Используется debounce 500 мс, поэтому фильтрация запускается только после небольшой паузы после ввода текста.

### Избранное

Состояние избранного изменяется через REST API.

При нажатии на сердечко выполняется запрос на сервер, поэтому значение сохраняется даже после повторной загрузки данных.


## Week 6 — Локальное хранение данных

На шестой неделе в приложение было добавлено локальное хранение данных.

### SharedPreferences

SharedPreferences используется для хранения пользовательских настроек:

- выбранная тема;
- выбранный язык.

Настройки сохраняются между запусками приложения.

### Локализация

Добавлена локализация приложения на русский и английский языки.

Используются:

- flutter_localizations;
- gen-l10n;
- ARB-файлы;
- Locale через Riverpod.

При изменении языка интерфейс приложения перестраивается автоматически.

### Hive

Hive используется для локального кэширования списка воспоминаний.

После успешного получения данных из REST API они сохраняются в локальный кэш.

### Offline-first

Реализована стратегия offline-first:

1. приложение сначала пытается получить данные из REST API;
2. при успешном запросе данные сохраняются в Hive;
3. если сеть или API недоступны, приложение загружает последние сохранённые данные из Hive.

Благодаря этому экран воспоминаний остаётся доступным без соединения с сервером.

### Избранное

Состояние избранного сохраняется локально в Hive.

Если сервер недоступен, пользователь всё равно может изменить состояние избранного локально.

## Week 7 — Navigation and Adaptive UI

Навигация приложения работает через `GoRouter` и `MaterialApp.router`. Основные маршруты: `/` (главная), `/drops` (список), `/drops/:id` (детали), `/create`, `/profile`, `/settings` и `/login`. В маршруте `/drops/:id` параметр `id` определяет, какое воспоминание показать; если запись не найдена, отображается сообщение об этом.

Главная, список воспоминаний, создание и профиль объединены в `StatefulShellRoute.indexedStack`. Благодаря этому состояние вкладок сохраняется при переключении. На телефоне вкладки показаны через Material 3 `NavigationBar`, на планшете — через `NavigationRail`.

Маршрут `/profile` защищён: без входа приложение перенаправляет на `/login`. Кнопка входа открывает профиль, а выход возвращает на экран входа. Это локальная демонстрационная авторизация на Riverpod; Firebase Authentication запланирована на Week 8.

Интерфейс адаптируется к телефону и планшету с порогом 700 px. Контент ограничен по ширине на больших экранах; длинный текст не выходит за границы, а экраны прокручиваются при небольшой высоте. Поддерживаются portrait и landscape.
